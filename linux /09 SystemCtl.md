**Systemctl** — это основной инструмент управления системой и службами в дистрибутивах Linux, использующих систему инициализации **systemd**. Он позволяет запускать, останавливать, перезапускать службы, управлять их автозагрузкой и проверять состояние системы.

### Работа с состоянием системы

Команды для управления питанием всего компьютера:

- **`systemctl poweroff`** — Выключение системы.
    
- **`systemctl reboot`** — Перезагрузка системы.
    
- **`systemctl suspend`** — Переход в спящий режим.
    
- **`systemctl hibernate`** — Переход в режим гибернации.


### Полезные возможности

- **Просмотр всех служб:** `systemctl list-units --type=service`
    
- **Просмотр только активных служб:** `systemctl list-units --type=service --state=running`
    
- **Проверка на наличие ошибок (failed):** `systemctl --failed`


## Маскирование служб (Masking)

Иногда отключения (`disable`) недостаточно: другой сервис или скрипт может автоматически запустить службу по зависимости. Для полной блокировки используется маскирование.

```
# Заблокировать службу (связывает .service файл с /dev/null, запуск станет невозможен)
sudo systemctl mask nginx

# Снять блокировку
sudo systemctl unmask nginx
```


### Базовые команды управления службами

_Синтаксис: `systemctl [команда] [имя_службы]`_

команда            описание
`start`        Запустить службу прямо сейчас.
`stop`          Остановить работающую службу.
`restart`    Перезапустить службу (остановить и запустить снова).
`reload`      Перечитать конфигурационные файлы без полной остановки.
`status`      Показать текущее состояние (работает/остановлена/ошибки).
`enable`      Добавить службу в автозагрузку. !
`disable`    Убрать службу из автозагрузки. !
`is-active`Проверить, активна ли служба в данный момент.

### Разбор вывода `systemctl status`:

- **`Loaded:`** Путь к `.service` файлу и статус автозагрузки (`enabled` / `disabled`).
    
- **`Active:`**
    
    - `active (running)` — служба работает.
        
    - `inactive (dead)` — служба остановлена.
        
    - `failed` — служба завершилась с ошибкой.
        
- **`Main PID:`** Идентификатор основного процесса в системе.
    
- **`Tasks` / `Memory` / `CPU:`** Ресурсы, потребляемые службой (благодаря Cgroups).

### служба это
В терминологии `systemd` служба — это процесс (демон), который живет в фоновом режиме. Он описывается специальным файлом конфигурации с расширением `.service`.

`systemctl list-units` - это команда для просмотра всех объектов, которые **сейчас активны** в системе под управлением `systemd`

---

- **Процесс (Process)** — это **конкретная программа в ОЗУ** с выделенным PID (физический уровень ядра Linux).

- **Служба / Демон (Service)** — это **роль программы**, которая постоянно работает на заднем плане без вашего участия (веб-сервер, база данных, SSH).

- **Юнит (Unit)** — это **конфигурационный файл для `systemd`** (`.service`, `.timer`, `.socket`), который объясняет системе, _как именно_ этой службой управлять (как запускать, откуда, и что делать при падении).
