f### Що таке процес?

**Процес** — це екземпляр програми, що виконується. У Linux кожен процес має унікальний ідентифікатор — **PID** (Process ID).
### Базові команди для моніторингу

- **`ps` (Process Status):** Показує список поточних процесів.
    
    - `ps aux` — вивести всі процеси для всіх користувачів у детальному вигляді.

### 4. Состояния процесса

Каждый процесс находится в одном из состояний, отображаемых в колонке `STAT` (`ps aux`).

**Основные состояния:**

| Символ | Название              | Описание                                                                                                                          |
| ------ | --------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| R      | Running               | Выполняется или в очереди на CPU.                                                                                                 |
| S      | Sleeping              | Прерываемое ожидание (ввод, сеть, таймер). Реагирует на сигналы.                                                                  |
| D      | Uninterruptible sleep | Ожидание I/O, который не прерывается сигналами.                                                                                   |
| T      | Stopped               | Процесс приостановлен сигналом SIGSTOP или SIGTSTP (Ctrl+Z). Не выполняется и не потребляет CPU. Можно возобновить через SIGCONT. |
| Z      | Zombie                | Завершён, но родитель не забрал код возврата через wait()                                                                         |
| I      | Idle                  | Неактивный поток ядра                                                                                                             |
**Модификаторы состояния:**

1. `<` — высокий приоритет
    
2. `N` — низкий приоритет
    
3. `s` — лидер сессии
    
4. `l` — многопоточный
    
5. `+` — на переднем плане
    

Пример: `Ssl` — спит, лидер сессии, многопоточный.



- **`top` / `htop`:** Інтерактивні диспетчери задач (як "Диспетчер завдань" у Windows). `htop` зручніший та візуальніший.
    
- **`pgrep`:** Пошук PID процесу за його назвою.


PID 1 (systemd) — 1-ый процесс в пользовательском пространстве. От него ведут начало все остальные процессы, если процесс теряет родителя — PID 1 его усыновляет, предотвращая накопление зомби.
PID 2 (kthreadd) — прародитель всех потоков ядра. От него создаются системные воркеры (к примеру kworker). В ps и htop их видно по квадратным скобкам [kworker/0:0]. Эти процессы работают в пространстве ядра и отвечают за фоновые задачи, такие как обработку прерываний, работу с диском итд.


команда **`nice`** використовується для запуску процесу з модифікованим пріоритетом
**Діапазон значень:**

- Від **-20** (найвищий пріоритет — процес "жадібний", отримує максимум ресурсів).
    
- До **19** (найнижчий пріоритет — процес "люб'язний", віддає ресурси іншим).
    
- За замовчуванням нові процеси запускаються зі значенням **0**.

***Якщо ви просто введете `nice -n 10 <команда>`, система запустить її з пріоритетом 10.***
#### Зміна пріоритету вже запущеного процесу (`renice`)

Якщо програма вже працює, `nice` її не змінить. Для цього існує команда `renice`.

- **Синтаксис:** `renice -n -p <значення> <PID>`
    
- **Приклад:** Змінити пріоритет процесу з PID 1234 на 5:
    
    Bash
    
    ```
    renice -n 5 -p 1234
    ```
`htop -p 1234` - щоб проверить результат
Флаг `-p` у команді `renice` вказує системі, що наступне число — це саме **PID**
### Як перевірити поточний пріоритет

Ви можете побачити колонку `NI` (niceness) у виводі команд:

- **`top` або `htop`:** Шукайте колонку з назвою `NI`.



### Керування процесами (сигнали)

Для керування процесами використовується команда **`kill`**, яка надсилає сигнали. Найважливіші сигнали:

1. **SIGTERM (15):** М'яке завершення (за замовчуванням). Програма встигає зберегти дані.
    
2. **SIGKILL (9):** Негайне примусове завершення. Процес вбивається без попередження.
    

**Приклади:**

- `kill <PID>` — завершити процес м'яко.
    
- `kill -9 <PID>` — вбити процес примусово.
    
- `pkill <назва>` — завершити всі процеси за назвою.
pkill -9 -f "Civilization" - пример
Флаг `-f` заставляет систему искать в полном пути запуска



**У Linux «фоновий режим»** означає виконання процесу без прив’язки до активного термінала, або запуск програми, яка продовжує працювати після того, як ви закрили командний рядок.

Ось основні способи керування фоновими процесами:

### 1. Запуск нової команди у фоні

Щоб запустити команду у фоновому режимі відразу, додайте символ **`&`** у кінці команди:

Bash

```
long_running_command &
```
Термінал відразу видасть `PID` (ідентифікатор процесу) і дозволить вводити нові команди.

| **Команда** | **Що робить**                                                 |
| ----------- | ------------------------------------------------------------- |
| `command &` | Запуск у фоні                                                 |
| `Ctrl + Z`  | Призупинення процесу                                          |
| `bg`        | Відновлення призупиненої програми у фоні                      |
| `jobs`      | Список фонових завдань                                        |
| `fg %n`     | Повернення процесу на передній план (який ви бачили у `jobs`) |
| `kill %n`   | завершує фоновий процес за його номером у списку `jobs`       |
(n - ном. процесу, не айди, можна побачити у `jobs`)
