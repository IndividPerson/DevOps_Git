**`journalctl`** — это утилита командной строки в Linux, которая используется для просмотра и анализа логов, собранных системной службой **`systemd-journald`**.

**Логи (журналы)** — это текстовые записи (или «дневник»), в которые система, программы и сервисы автоматически записывают всё, что с ними происходит.

В них фиксируются:
- **События:**
- **Ошибки и сбои:**
- **Предупреждения:** Нехватка памяти, подозрительная активность.
- **Действия пользователей:**
- 
Если в системе что-то ломается или работает не так, **логи — это первое место, куда смотрят**, чтобы понять причину.

---

## 1. Базовая навигация

При вызове без параметров `journalctl` открывает **все доступные в системе логи** с самого раннего записанного момента через утилиту навигации `less`.

Bash

```
journalctl
```

### Основные горячие клавиши (в режиме less):

- `j` / `k` (или стрелки) — построчная прокрутка вниз / вверх.
    
- `G` — перейти в самый конец логов (к последним событиям).
    
- `g` — перейти в самый начало.
    
- `/текст` — поиск по тексту (нажмите `n` для перехода к следующему совпадению).
    
- `q` — выход из режима просмотра.

## 2. Фильтрация по времени

|**Команда**|**Описание**|
|---|---|
|`journalctl -b`|Логи **текущей загрузки** системы.|
|`journalctl -b -1`|Логи **предыдущей загрузки** (`-2` — предпредыдущей и т.д.).|
|`journalctl --since "1 hour ago"`|Логи за последний час.|
|`journalctl --since "2026-07-30 10:00:00"`|Логи начиная со указанной даты и времени.|
|`journalctl --since "2026-07-29" --until "2026-07-30 12:00:00"`|Логи за конкретный временной интервал.|


```
# Логи конкретной службы systemd (например, NetworkManager, sshd, nginx)
journalctl -u NetworkManager.service

# Логи нескольких служб одновременно
journalctl -u NetworkManager -u sshd

# Логи конкретного процесса по его PID
journalctl _PID=1234

# Логи исполняемого бинарника по абсолютному пути
journalctl /usr/bin/dbus-daemon
```

```
# Режим "живого" потока (Follow)
journalctl -f

# Последние 50 строк службы SSH + отслеживание новых
journalctl -u sshd -n 50 -f
```


## 5. Фильтрация по уровням важности (Priority)

Параметр `-p` (или `--priority`) позволяет отсеять менее важные сообщения.

| **Уровень (Строка / Номер)** | **Описание**                          |
| ---------------------------- | ------------------------------------- |
| `0` / `emerg`                | Система непригодна для использования. |
| `1` / `alert`                | Требуется немедленное вмешательство.  |
| `2` / `crit`                 | Критические условия.                  |
| `3` / `err`                  | Ошибки (Error).                       |
| `4` / `warning`              | Предупреждения.                       |
| `5` / `notice`               | Нормальные, но важные события.        |
| `6` / `info`                 | Информационные сообщения.             |

```
# Показать только ошибки и критические сбои (уровни 0-3)
journalctl -p err

# Ошибки конкретной службы за текущую загрузку
journalctl -u nginx -b -p err
```


## 6. Логи ядра (Kernel Logs)

Аналог команды `dmesg`, выводит сообщения ядра Linux (инициализация железа, драйверы, сообщения об ошибках RAM/диска):

```
journalctl -k
```



## 7. Форматы вывода и управление размером

```
# Вывод без пейджера less (сразу весь список в терминал)
journalctl --no-pager

# Вывод в формате JSON (удобно для парсинга скриптами)
journalctl -o json-pretty -n 1

# Посмотреть текущий объем диска, занятый логами
journalctl --disk-usage

# Очистить логи, оставив только последние 500 МБ
sudo journalctl --vacuum-size=500M

# Очистить логи старше 2 недель
sudo journalctl --vacuum-time=2weeks
```
